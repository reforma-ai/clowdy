## Claude Code

### What each source is (ranked by how little credential handling it needs)

**1. ACP `/usage` prompt through the adapter (A).** `[observed]` In `claude-agent-acp@c5c120d`, a prompt whose only content is the text `/usage` is "the structured replacement" case: Claude Code still runs the command, the adapter calls the SDK control request (B) with a 5 s timeout and replaces the command's text with Markdown (`src/v1/acp-agent.ts:481` `STRUCTURED_USAGE_TIMEOUT_MS = 5_000`, `:554-585` `structuredUsageMarkdown`, `:2324-2340` `localCommandMarkdown`). On timeout, an unparseable answer or an error it forwards Claude Code's own `/usage` text unchanged (`:566-583`). The Markdown shape (`src/usage-markdown.ts:126-134`, `:168-190`):

```markdown
## Usage
> Claude max subscription usage
### Limits
**5-hour limit** — **8%** · Resets Nov 18, 3:00 PM PST
`█░░░░░░░░░░░░░░░░░░░`
**Weekly · all models** — **20%** · Resets ...
**Weekly · Fable** — **0%**
### This session  | Cost | API time | Active | ...
```

Observations: the limit rows are printed only when `usage.rate_limits_available && usage.rate_limits` (`:175`); `Weekly · <model>` uses `model_scoped[].display_name`, with `seven_day_opus`/`seven_day_sonnet` only when `model_scoped` is empty (`:179-186`); `extra_usage` is **not** rendered; the reset is a display string from `Intl.DateTimeFormat("en", ...)` with a short time-zone name (`:116-124`), so the ISO instant is lost. No structured field rides along: `grep usage_report` over `src` at `v0.107.0` and at `main` `96dd2bb` finds nothing outside tests. A client would parse text by label.

### Per account

- The unit of account is the config directory: `CLAUDE_CONFIG_DIR` gives "its own settings, session history, and claude.ai login or API key" (authentication page), and the Keychain entry is keyed to it. `claude auth status --json` reports `configDirectory` (2.1.268+), so the directory the CLI actually used can be confirmed.
- Orca keeps one reading per saved account and tags a reading with `readingAccount` and an auth provenance, so a switch discards stale quota (`rate-limit-types.ts@3941b73d` `UsageReadingAccount`, `usageMetadata.authProvenance`); inactive accounts are read at most once per 60 s (`INACTIVE_FETCH_DEBOUNCE_MS`, `service-types.ts:102`).
- bb: `accountKey` is "Provider-issued quota account identity, namespaced by issuer ... Never use email, a display label ... Null means unknown; unknown accounts must not be merged" (`usage-source-contract.ts@48c3a78:62-70`); Claude uses `anthropic:account:<accountUuid>`.
- Windows are per login, not per machine: two config dirs with the same login would show the same numbers (the dedupe in `selectUsageResources`, `usage-normalization.ts:62-79`, exists for that).

## Reference implementations: fetch, cache, data model

### Orca (`3941b73d`)

- **Polling.** `DEFAULT_POLL_MS = 15 min` ("Informational Claude quota has a tight endpoint budget; prefer recent snapshots to 429s"), `MIN_POLL_MS = 30 s` floor, `MIN_REFETCH_MS = 5 min` ("don't refetch a fresh reading"), `STALE_THRESHOLD_MS = 30 min`, `LONG_STALE_THRESHOLD_MS = 24 h` for 429s and Claude's lapsed-token state, `INACTIVE_FETCH_DEBOUNCE_MS = 60 s` for non-active accounts (`src/main/rate-limits/service/service-types.ts:83-103`). Polling runs **only while someone watches** (window visible, not minimized, focused, or a remote viewer attached; `service-polling.ts:shouldBackgroundPoll`), and focusing the window triggers a refresh plan: full refresh if any provider is idle/fetching or its last check is older than 5 min; otherwise only failing providers whose backoff is due (`:getActiveWindowRefreshPlan`). Failure retry starts at 30 s and doubles per consecutive failure up to the 15 min poll interval (`failureRetryDue`, streak capped at 8).
- **429 and `Retry-After`.** The header is parsed and capped at 24 h (`providers/usage-retry-after.ts`); the result carries `usageMetadata.retryAtMs`; automated fetches skip a provider while `retryAtMs` is in the future, but a user-initiated refresh may pass (`service-fetch-policy.ts:shouldSkipAutomatedFetch`). Claude 401/403/429 are "authoritative" and do not trigger any fallback (`claude-oauth-usage-error.ts`). Message for 429: "Claude usage is rate limited right now."
- **Stale-while-revalidate.** On an error result the previous reading is kept (with `status: 'error'`, the new error text and `failureKind`) until it is older than the threshold, so bars do not flash empty (`service-result-policy.ts:applyStalePolicy`); windows whose `resetsAt` has passed are dropped from any retained reading by `withoutResetWindows` ("a window past its reset no longer describes the account, and 0% would hide use on another device"). Within one window usage only grows, so a lower percent with the same reset, or an older reset, is treated as an idle session's stale snapshot (`claude-usage-window.ts:isStaleClaudeUsageWindow`, tolerance 60 s).
- **Live feed.** A managed status-line script POSTs the payload (only if it contains `rate_limits`, at most every 15 s per pane, dedupe 30 s on the receiving side) to a local loopback server with a per-process token; "Claude >=2.1.80 supplies rate_limits via statusLine from API responses, avoiding usage-endpoint polling that 429s under Orca" (`claude-statusline-rate-limits.ts:1`). `claudeOAuthUsageEnabled` defaults to `true` (`default-global-settings.ts:260`); when the user turns it off, only the live feed remains. The script is installed into the user's Claude `statusLine` setting, with a marker so a user deletion is not reinstalled (`statusline-install.ts`).
- **Codex order.** auth presence check (no `auth.json` means `unavailable`, "Codex not signed in"), then `app-server` RPC under a per-home lock, then HTTP `wham/usage` as fallback and as a supplement for missing windows and reset credits; WSL and "state DB backfill pending" go straight to HTTP "so it cannot contend with the backfill" (`codex-fetcher.ts:160-255`).
- **Data model.** `ProviderRateLimits { provider, session: RateLimitWindow | null, weekly, fableWeekly?, monthly?, extraUsage?, buckets?: RateLimitBucket[], rateLimitResetCredits?, planType?, updatedAt, error, status: 'idle'|'fetching'|'ok'|'error'|'unavailable', usageMetadata? { source: 'oauth'|'cli'|'web'|'live-session', failureKind, retryAtMs, readingAccount, ... } }`; `RateLimitWindow { usedPercent 0-100, windowMinutes, resetsAt (ms) | null, resetDescription }`; `RateLimitBucket = RateLimitWindow & { name, group?, windowName? }` (Cursor pools, Gemini models); `ExtraUsageBalance` is a union of `currency { balance, currencyCode, enabled, spent, spendLimit, spentPercent, resetsAt }` and `credits { balance, unlimited }` (`src/shared/agent-usage/rate-limits/rate-limit-types.ts`). `failureKind` is a closed list: `missing-credentials`, `stale-token`, `keychain-unavailable`, `missing-scope`, `no-subscription`, `network`, `server`, `parse`, `rate-limited`, `cli-unavailable`, `usage-unavailable`, `unknown`, ....
- **Signed out or unsupported.** Claude with no token on the system-default account is `unavailable` with "No subscription plan — API key billing" (it may be an API-key user); with a named profile it is `error` "Sign in again to use this account."; Cursor `unavailable` "No Cursor sign-in on this computer — sign in with Cursor IDE or `cursor-agent login`"; a Cursor plan with no allowance is `unavailable` "Cursor reported no usage allowance for this account". The roster row state is one of `usage | loading | sign-in | unavailable | error | empty` and a sign-in call to action appears only for a proven sign-out (`missing-credentials` or matching text), never for a network or refresh failure (`UsageRosterPanel` row state `usage-roster-row-state.ts`).
- **Status bar and popover data model.** One chip per provider. The headline window is the one with the **highest clamped used percent** among "primary" windows (session, weekly, monthly/plan, buckets); scoped windows (Fable, ZCode MCP) are excluded from the roster headline and shown separately when at or above a threshold; the status bar uses scope `all`; for Cursor the headline is the `Cursor Models` bucket (`usage-headline-sections.ts:getTightestUsageSection`, `getUsageHeadlineSection`). Health tone follows consumption: warning at used ≥ 80, urgent at ≥ 90, whichever of used/remaining the user chose to display (`usage-health-tone.ts:4-6`); the `used`/`remaining` toggle rounds used first, then complements (`usage-percentage-display.ts`). The popover (`UsageRosterPanel.tsx`) lists providers sorted by their primary max used percent descending, has a refresh action and a segmented control `StatusBarUsageMode = 'verbose' | 'compact'`: Detailed (`verbose`) "Full usage with bars, labels, and percentages", Compact "Condensed usage: one summary per provider". Reset text ("resets in 3h 35m", "resets now") is computed on the client from `resetsAt` with a ticking clock (`usage-reset-caption.ts`, `useResetCountdownClock.ts`).

### bb (`48c3a78`)

- **Contract.** The bridge method is `provider/usage`; support is declared per provider and "a successful usage result may likewise contain an empty `windows` array" (`docs/provider-bridge-protocol.md:81-89`). The usage plugin's source contract is `provider-usage.v1.listResources` ("cheap complete inventory ... reads local metadata only; never refreshes quota") and `provider-usage.v1.getResource { resourceId, refresh }` ("False permits a cached measurement ... True requests a fresh collection attempt for this resource only"). A measurement is `{ accountKey | null, observedAt (ms) | null, usage }` with `usage` a union on `status`: `ok { plan { id, multiplier } | null, accountEmail, planLabel, windows[] }`, `not_installed`, `unauthenticated`, `expired`, `error { message }`; a window is `{ kind: 'five-hour'|'daily'|'weekly'|'custom', id, label, usedPercent (≥ 0, "may exceed 100 for overage"), resetsAt (ISO) | null, model | null, cost { usedUsdCents, limitUsdCents } | null }` (`plugins/provider-usage/usage-source-contract.ts`). Labels are derived: `Five-hour limit`, `Weekly limit`, and `Weekly · <Model>` when `model` is set (`usage-normalization.ts:21-44`).
- **Caching.** The UI asks with `maxAgeMs`: card 2 min, window refocus 5 min, safety refresh every 30 min (`plugins/provider-usage/app.tsx:63-65`); fetches run three at a time; unopened provider tabs are not measured; "Failed refreshes retain the last available measurements with a retry notice. Account authentication failures and plans without reported limits have separate states; unavailable usage is never represented as zero consumption." (`README.md`).
- **Claude without a token**: the throwaway SDK session (B). **Codex, Cursor, OpenCode Go**: token reads (N, Q, `opencode-usage.ts`). **Account Pooler** (experimental) calls the OAuth usage endpoint and `wham/usage` with pooled tokens every 5 min, 30 s while an account is exhausted (`plugins/account-pool/src/hub.ts:46-50`), and also reads the unified headers off proxied traffic.
- **Retry plugin** (`plugins/provider-retry`): uses a reset time when the subscription limit reports one, "a little past the reset" plus jitter; credit and spend limits are not retried (existing note `bb-source.md`).
