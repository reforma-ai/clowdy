# File manager (`@clowdy/file-manager`)

A file tree and a text editor over any file system, forked from Reforma's `packages/file-manager`. It knows nothing of the daemon or of Electron: everything it reads and writes goes through a `FileSystemProvider` (`src/provider.ts`, with the contract in its comments), so the same code runs on the daemon's folders (`apps/desktop/src/renderer/daemon/httpFileSystem.ts`) and on `MemoryFileSystem` (tests, the fixture daemon). Paths are POSIX and relative to the provider's root; versions are opaque and only compared.

## Layout

```
src/FileManager.ts       One manager: tree, tabs, operations, search, the host's file clipboard, the filter; start/refresh/restore/snapshot
src/tree/FileTree.ts     The listing as an index (depth-3 first listing, folders loaded as they open), patched by watch changes, with exclude/hidden globs
src/documents/           TextDocument (load, edit, save with a version check, conflicts, rich Markdown, SVG preview) and Tabs
src/FileOperations.ts    Create, rename, move, copy, import (files the host's clipboard names from outside), delete, upload, with confirmations and the tree's bookkeeping
src/search/              Text search through a provider (or a host's SearchService)
src/memory/              MemoryFileSystem: a whole provider in memory, with versions, errors and watch events
src/react/               FileManagerView (the editor at the left, the sidebar with the file tree at the right on an edge to drag), Explorer (react-arborist), EditorArea (tabs from `TabStrip` of `@clowdy/components`, which the desktop's Terminal tab uses too, CodeMirror, Markdown pane)
src/react/diff/          DiffView: a read-only unified diff of two texts on `@codemirror/merge`, in the editor's look; not in Reforma
specs/                   Vitest, in Node (`bun run test`): the manager, the tree, the documents, the operations, the search, the memory provider; the diff view runs in happy-dom (`// @vitest-environment happy-dom`)
```

## Rules

- **The least widths are the host's to hold.** The editor can be dragged no narrower than 350px and the sidebar no narrower than 150px (`src/react/layout.ts`, exported as `@clowdy/file-manager/layout`, which has `FILE_MANAGER_MIN_WIDTH` for their sum): a host that puts the view in a column keeps the column from being narrower than that, and the desktop app puts Files and Docs in the chat's place where its window has no room for it beside the chat.
- **Never import the app.** The host gives a provider, the options (`exclude`, `hidden`, `notify`, `saveParticipants`, `search`) and, to the view, `sidebarOpen`, `sidebarWidth`, `onSidebarWidthChange` and `onSidebarToggle`. Finding a file by its name or its content is the host's (`manager.open(path, selection)` opens the result, `manager.search` runs the content search, `manager.selectedText()` is what the open file has selected). Add a host hook when something needs the app, not an import.
- **Differences from Reforma**, so a port of a later Reforma change knows where to look: the sidebar is at the right and resizable (`FileManagerView` is a `ResizablePanelGroup`, the sidebar panel built each time it opens with an id of its own, as `SidePanelLayout` does, and the group itself built once the view's box has a width: a host that mounts the view in the same pass that sizes its column, as the side panel does when it opens again, would otherwise get a group laid out in an unsized box, with the tree at its narrowest for good); the Explorer likewise draws its tree once its host has a size and takes the list's offset from the element after every resize (a tree built with no size and asked to reveal the open file could be left drawing the rows for an offset the element was not at, with the rows above blank, until something scrolled it); the editor's tab strip is always there, with an optional toolbar slot, and the sidebar's header is the tree's filter field (`FilterField` in `FileManagerView`, with the toggle after it) in place of a title: there is no Search tab, no filter button to open it, no `filterOpen` and no ⌘P or ⇧⌘F (`SearchView` is gone: the host's palette searches the files and their text through `manager.search`, `manager.listedFiles` and `manager.open`), the field is drawn by the view and `ExplorerHandle.openFirstMatch` is its Enter, and the filter also finds what the tree has listed that the provider's search does not know (`listedFiles`, git-ignored files); the header has no `⋯` menu (`ExplorerPanelMenu` is unused: a host puts New file, New folder and Paste in the row menus, and "show hidden files" in a key and a setting); `onSidebarToggle` makes the Folder button that shows and hides the sidebar, at the end of the tab strip while it is hidden and at the end of the sidebar's header while it shows, so it stays in one place; Copy and Paste go through the host's system clipboard (`FileManagerOptions.clipboard`, a `FileClipboard` in `provider.ts`) where Reforma keeps a list of copied paths in the manager and puts `@path` text on the clipboard: Copy writes the items there as files, Paste reads what is there and has the provider copy what the tree lists (`FileOperations.copy`, a folder pasted on itself goes next to itself) and the host copy the rest, which came from outside or is not listed (`FileOperations.import`); without a host clipboard (`canCopy`, `canPaste`) the tree has no Copy and no Paste; `FileManagerView` and the explorer take an optional `scope` (`ExplorerScope`: `roots`, which entries are rows, how a new file is named, a label), which draws a part of the manager's own tree, such as the folders of documents inside hidden folders, in the same rows beside the same editor and tabs: each root (`{ id, label, root }`, in the order given; `roots` may be a getter that reads observable state, and the explorer and the view, which are observers, follow its changes) is drawn as a gray label row (`ExplorerItem.heading`, id `HEADING_PREFIX` + the root's id: a synthetic row that is not an item of the tree, with `role="presentation"`, no click that selects it, `disableSelect`, `disableEdit` and `disableDrag`, a right-click menu of its own with New file, New folder and Paste in its root, and files dropped from outside on it going in its root) followed by the root's rows, which are `FileTree.entriesOf(root)` that the scope's `include` passes (the hidden and excluded globs do not apply); a root with no row is not drawn (unless the inline new row is in it), each root is listed whole by `FileTree.loadDeep` once the tree is ready and again when the set of roots changes (a folder listed deep is remembered: a resync lists it once, whole, and not every folder below it, and a folder that is gone since, which a resync said nothing of, is forgotten instead of failing the refresh; a `loadDeep` asked for while a refresh is in flight is run once that refresh has committed), the scope has a name filter of its own (`scopeFilter`, over the listed entries of every root, matching the path below the root, since the provider's search can leave its folders out; a label stays only while its root holds a match), and a new row, a paste and a drop default to the first root that has rows (the first one when none has; a scope with no root offers none), a row's menu to its own folder, and a drop at the top level of the tree to the root whose label is above that place (`rootAtIndex`); the platform check is `src/react/platform.ts` (no `@reforma/lib/hotkeys`); the Explorer's react-dnd HTML5 backend listens on the tree's own element (`dndRootElement`, so the tree renders once its host element exists), not on the window, where it would cancel the native drags of the app's other screens (the task board's cards) and the drops of text into fields; the empty editor shows the `Page` icon in place of Reforma's logo; styles read Clowdy's tokens and `--clowdy-listbox-*`; a PDF is shown in the browser's viewer in a frame of a `blob:`, which the host's content security policy has to allow (`frame-src blob:`, as Reforma's does). The rest is Reforma's.
- **`DiffView` (`src/react/diff/`) shows two texts of one file, not a document.** Props: `path` (its extension picks the language, its name labels the text), `original` and `modified` (`null` for a side that is not there: no `original` shows every line added, no `modified` shows every line removed and no line numbers), `extensions` (a host's CodeMirror extensions, such as Add to chat: they live in a compartment, so a new set replaces the old one without building the state again or losing the selection; they come after the editor's own keymap, so a key it binds, such as `Mod-i` for select parent syntax, needs `Prec.high`), `lazy` (builds the editor only once the view is within 800px of the viewport, through one `IntersectionObserver` that takes the nearest scroll container of the view as its root, because a margin does not reach past a scroll container's edge when the root is the viewport, and then keeps it, so the list does not jump; until then a box of `estimatedLines` lines, or `estimateDiffLines` of the two texts, stands in, and no language is loaded), `className`. It is `unifiedMergeView` (unified only, `mergeControls: false`, `gutter: false`) over `EditorState.readOnly`, so the text stays focusable and selectable and a host reads the selection from the state; unchanged runs fold behind a row (3 lines of context, at least 5 folded), the diff is cut off at 200 ms and runs with no depth limit (the merge package's default limit of 500, meant for text being typed, turns a file of 1000 lines with 25 edited ones into one chunk of the whole file; `original` is cut at the same line breaks as the document, a lone CR included), lines do not wrap, the horizontal scroll is the editor's ScrollChrome. The editor's chrome is copied into `DiffView.module.css` and not shared with `CodeEditor.module.css` (change both for a look that applies to both); added lines read `--color-success-*` and removed `--color-danger-*`, each with a 3px edge on its left and no shadow, and the merge extension's own colors are overridden with `!important` because its theme is stronger than a class. The language is loaded before the editor is built (a removed block is drawn once, with the language it had then). Changing `original`, `modified`, `path` or the language builds a new state in the same view (folded rows fold again, the selection goes; texts equal to the ones shown change nothing, and a path whose language is still loading keeps the language it had until it arrives); the view is destroyed with the component. A file with no earlier text skips the merge extension (it would draw the empty text as one removed blank line), and the removed lines of a changed or deleted file are widgets, not text of the document, which `unifiedMergeView` cannot change: a selection button sees only the lines that exist now, and the editor's state holds no removed text for it to quote. Specs: `specs/diff-view.test.ts`.
- **A provider fails with `FileSystemError`** and one of its five codes; the manager acts on the code (a `Conflict` is "Changed on disk", a `NotFound` closes a clean tab). A provider that cannot tell what changed sends `{ type: 'resync' }` and the manager lists again.
- **Text is UTF-8** (`decodeUtf8`): a file that is not is binary and opens as a preview or a note. Text over 5 MB and media over 50 MB do not open.
- **Test with `MemoryFileSystem`**, never a real disk. The Explorer and the editor need a browser and have no unit tests; look at them with the desktop app's screenshot harness (`?fixtures=static&panel=open&panelTab=files`).
